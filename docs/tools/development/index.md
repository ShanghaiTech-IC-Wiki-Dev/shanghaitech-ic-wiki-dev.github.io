# EDA 环境与 Linux

上科大往届课程资料中出现过课程服务器、云桌面，以及经申请使用的 EDA 集群。这些环境**不是同一套资源，也不保证工具、许可证和工艺库完全相同**。当前使用资格、开通流程、保存期限与资源限制，应向**学院电子学科平台或课程助教申请和确认**。

本页只介绍通用方法，不提供接入地址、账号、密码或管理人员联系方式。不要将这类信息补充到公开 Wiki、截图或代码仓库中。

## 先确认环境，再开始实验

| 环境 | 通常怎样使用 | 应提前确认 |
| --- | --- | --- |
| 课程服务器 / 云桌面 | 按助教提供的入口和实验说明操作 | 课程版本、工作目录、存储期限、备份范围与提交方式 |
| 经授权的 EDA 集群 | 登录后通过调度器运行计算任务 | 队列、核数、内存、交互图形方式、可用工具模块 |
| 自己的电脑 | 编辑、Git、文档、开放工具与小规模验证 | 商用工具许可及受限数据能否离开学校环境 |

迁移课程实验前检查三件事：**工具及版本是否存在、许可证是否覆盖、PDK 与库是否获准且匹配**。不要因为能启动 Virtuoso，就推断 Genus 或 Innovus 也可用；不要自行复制许可证配置或受限工艺资料来补环境。

## Linux：先学够用的命令

| 命令 | 用途 | 安全习惯 |
| --- | --- | --- |
| `pwd`、`ls -lah`、`cd` | 定位当前目录和文件 | 运行脚本前确认目录，不依赖终端打开时的位置 |
| `mkdir -p`、`cp`、`mv` | 创建目录、复制、移动 | 覆盖前确认目标；备份不是把大数据库无限复制 |
| `less`、`head`、`tail` | 阅读日志 | 用 `tail -f` 跟随正在运行的日志，退出查看不会停止作业 |
| `grep`、`find` | 查文本与文件 | 限定搜索目录，避免扫描共享存储和他人目录 |
| `du -sh`、`df -h` | 查看目录与文件系统空间 | 大波形、数据库和中间文件要按平台规则管理 |
| `ps`、`top` | 查看进程 | 集群作业优先用调度命令查询，不随意终止不属于自己的进程 |
| `chmod` | 设置权限 | 不用全员可写权限“解决”所有问题，不修改共享库权限 |
| `man`、`命令 --help` | 查看帮助 | 不明白参数时先读文档，尤其是删除与覆盖操作 |

Shell 中空格会分隔参数，路径变量通常应加双引号。`>` 会覆盖输出文件，`>>` 是追加，`2>` 重定向标准错误，管道把前一个命令的标准输出交给后一个。不要把“命令没有打印东西”等同于执行成功，应查看退出码和日志。

## 模块、远程图形与 X11

集群可能用环境模块（Environment Modules）管理软件版本：

```bash
module avail
module list
module load "$EDA_MODULE"
module list
```

`EDA_MODULE` 表示你按平台文档在本地设置的模块名，不是统一固定值。避免无目的地把多个版本叠加到同一 Shell；记录实际加载的版本。某个命令不存在时，先检查模块是否加载，不要立即自行安装另一份工具。

如果平台允许 SSH 图形转发，可按其指南使用 X11：

```bash
ssh -X "$EDA_LOGIN"
```

`EDA_LOGIN` 是平台私下提供、由你在本地设置的登录目标，**不要将其值提交到仓库**。本地还需要可用的 X Server；`-X` 不保证作业节点端也已配置图形转发。只有在可信环境且平台明确要求时才考虑可信转发 `-Y`。连接异常时按平台指南检查，不关闭系统安全设置来绕过问题。

## LSF：大任务必须进队列

**登录节点用于编辑、检查环境、提交和查询作业，不用于直接跑大规模仿真、综合、布局布线或签核。** 图形工具也可能消耗大量资源，应按规定申请交互作业后启动。

以下是 LSF 的通用示例。`BATCH_QUEUE`、`INTERACTIVE_QUEUE` 分别表示平台批准的批处理和交互队列名，需按当前指南在本地设置；`run.sh` 是你的实际作业脚本。

```bash
bqueues
bsub -q "$BATCH_QUEUE" -n 1 -J demo \
  -o 'demo_%J.log' -e 'demo_%J.err' bash run.sh
bjobs
bsub -Is -q "$INTERACTIVE_QUEUE" bash
```

`%J` 会由 LSF 替换为作业编号。按程序的真实并行度申请核数，并按平台规定申请内存、时限等资源；不要复制与任务不符的高配参数。交互 Shell 如何启动 GUI、是否需要额外 X11 选项，以平台配置为准。有的平台提供 `qrsh` 等交互封装，只有在平台指南明确支持时才使用。

拿到作业编号并在本地设置 `JOB_ID` 后，可查询详情或停止**自己的**作业：

```bash
bjobs -l "$JOB_ID"
bkill "$JOB_ID"
```

`bkill` 是终止操作，不是刷新命令。排队不等于运行失败；先看作业状态和调度原因。提交后保存编号、日志路径和运行参数，断开终端前确认任务由调度器管理；不要在登录节点用后台命令绕过队列。

## Tcl：把工具操作写成脚本

许多商用 EDA 工具使用 Tcl。先掌握变量、列表、命令替换、条件与循环：

```tcl
set project counter
set rtl_files [list counter.v tb_counter.v]
puts "Project: $project"
foreach src $rtl_files {
    puts "Input: $src"
}
```

这是标准 Tcl 的文件列表演示；`read_hdl`、`synthesize` 等 EDA 命令属于具体工具接口，不能在不同产品间照搬。应从课程提供的脚本开始，理解每一步输入、约束和报告；不要只复制一段无法解释的命令让流程“跑到最后”。

## Makefile 与 Git：减少重复，保留证据

下面的 Makefile 与 [开源工具页](/tools/open-source/) 的计数器示例配套，配方行开头必须是 **Tab**：

```makefile
.PHONY: sim wave

sim: sim.vvp
	vvp sim.vvp

sim.vvp: counter.v tb_counter.v
	iverilog -g2012 -s tb_counter -o $@ $^

wave: sim
	gtkwave counter.vcd
```

运行 `make sim` 完成编译与仿真，`make wave` 追加波形查看。更大的项目再按实际依赖增加综合与报告目标，不把全部操作塞进一个无法增量执行的长命令。

Git 优先记录 RTL、测试、约束、脚本和允许公开的文档。用 `git status` 看状态、`git diff` 看修改、`git log` 看历史；提交前逐文件确认。波形、工具数据库、大日志、PDK、许可证和凭证不应进入公开仓库。已有受限文件误入历史时，应按平台要求处理泄露，单纯删除当前文件不能清除历史。

## 本地编辑、云端运行的边界

可以在本地写代码、在授权环境运行 EDA，但同步前先区分自主源码和受限材料。使用 AI 或外部服务时，不上传 PDK、许可证配置、服务器信息、未公开网表或研究数据，除非已得到明确授权。同步也不应无差别覆盖服务器目录：先查看差异，保留正在运行任务依赖的输入。
