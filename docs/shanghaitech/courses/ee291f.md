# EE291F 数字 VLSI 设计流程

<CourseTable codes="EE291F" />

课程表采用 **2026–2027 学年**信息；下文具体课件与作业依据娄鑫老师公开页的 **2026 秋版本**。往届版本教师可能不同；公开资源页不等于全学期内容都已列齐。

## 课程定位

[EE113](/shanghaitech/courses/ee113)让你理解门电路的代价，EE291F 则把设计放进可运行、可交接的数字工程流程：源代码怎样进入工具，约束怎样影响实现，工具产物怎样被下一阶段正确使用。

官方先修为 EE113。建议熟悉 HDL、组合 / 时序逻辑、时钟与建立保持时间，并具备基本编程能力。不要求在选课前“学完所有 EDA 软件”，但应愿意使用命令行、读日志、维护脚本。它与[Cadence 暑期实训](/shanghaitech/courses/cadence-summer)相互补充：本页公开的 2026 秋资料侧重工程基础、综合与形式等价，暑期实训经验覆盖更完整的物理实现与签核。

## 内容主线

公开课程页列出以下八组课件：

| 顺序 | 主题 | 关键问题 |
| --- | --- | --- |
| 1 | Linux | 如何管理文件、进程、环境与批处理任务？ |
| 2 | VLSI Overview & EDA Tools | 各阶段工具的职责与输入输出是什么？ |
| 3 | Tcl、Git、Makefile | 如何表达工具操作、管理版本与组织可重复运行？ |
| 4 | Technology Files | 工艺与库文件分别给工具提供什么信息？ |
| 5 | Timing | 时序路径和约束怎样定义“足够快”？ |
| 6 | Genus 综合 | RTL 如何转换为带约束的门级实现？ |
| 7 | Design Compiler 综合 | 在另一套综合工具中理解同类任务 |
| 8 | Formality 形式验证 | 如何检查综合前后的逻辑等价性？ |

把时序约束看作设计契约，而不是为了得到漂亮报告而调整的参数。综合能完成，不代表约束完整；等价性通过，也不代表设计满足目标频率。

## 实验 / 项目

2026 秋公开页的 EE291F / CX291F 共用作业包含：

- **HW1：Genus 综合流程**。以 MohoTop 为对象，交付报告、综合网表、时序约束文件（SDC）与综合报告。
- **HW2：DC 与 Formality 流程**。完成综合与形式验证，提交报告、网表、SDC、标准延时格式（SDF）及工具报告。

这些任务训练的不是记住一串命令，而是完整解释交付物。建议报告按“输入与配置 → 执行流程 → 检查结果 → 问题解释”组织；至少能够说明顶层模块、时钟约束、库配置、综合结果和等价性检查分别来自哪里。

进行工具对比时，必须对齐 RTL、库、约束、工艺角与统计口径。若条件不同，只能报告各自结果，不能直接宣称某工具更优。

## 往届经验与建议

**2026 秋版本。** 公开页列出了两次作业及交付要求，但没有完整总评比例。本页不将两次作业等同于全部考核，也不推断是否有考试或期末项目。

- **难点**：库与约束不匹配、未约束路径、工具运行环境，以及读懂综合和形式验证日志。
- **准备**：掌握 Linux 基本命令、Git、Makefile 与简单 Tcl。理解输入、输出、错误信息，比背一整份参考脚本更重要。
- **调试**：先判断错误属于读入、展开、约束、映射、优化还是验证。保留第一处有效错误及完整日志，不只看最后一句失败。
- **可复现**：区分源码、配置与运行目录；一次实验绑定一组明确输入。修改约束后重新标记结果，避免覆盖旧报告却继续引用旧网表。
- **交付**：用报告说明实际完成与未通过的检查，不把进程退出码为零当作设计验收。
