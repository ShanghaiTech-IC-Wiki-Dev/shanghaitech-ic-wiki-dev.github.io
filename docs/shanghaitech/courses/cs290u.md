# CS290U 深度学习工程实践

<CourseTable codes="CS290U" />

课程表采用 **2026–2027 学年**信息；下文经验为 **2026 秋版本**。往届版本教师可能不同，且该学期笔记中的初始大纲与后续项目通知存在配分差异，应以最新正式通知为准。

## 课程定位

这门课不以“记住更多网络结构”为终点，而是让你完成数据准备、模型运行、训练或适配、评估、误差分析和成果展示。它适合将深度学习理论转化成可解释、可重复的工程实践。

官方开课表先修为 CS280；虽然往届笔记的基本信息写“先修无”，这里不把它解释成当前无先修。学习上还需要 Python、PyTorch、线性代数与基本优化知识。与[EE219](/shanghaitech/courses/ee219)搭配时，可将本课的模型与数据理解带到算子、量化和硬件映射中；但两门课的作业与成果不得未经许可互相替代提交。

## 内容主线

2026 秋初始安排可归并为以下阶段；周次是往届版本，不是下一学期承诺。

| 阶段 | 初始周次 | 主线与检查点 |
| --- | --- | --- |
| 理论与工程准备 | 1–2 | MLP、反向传播、CNN / RNN / Transformer，以及训练与工程基础 |
| 二维视觉 | 4–5 | 在新数据上测试分割、检测等方法，分析预处理与数据分布差异 |
| 相机定位与三维 | 5–6 | 理解几何、对应关系和位姿；核对坐标、尺度与评估口径 |
| 点云处理 | 7–8 | 特征提取、配准与新环境中的误差分析 |
| 自定义项目 | 9–12 | 文献调研、方案、实现、评估、报告与展示 |

后续笔记中的项目题目更具体，包括分类 / 检测 / SAM，以及 VGGT、VGGT-Omega、AnySplat 等前馈三维重建方法。因此学习路线应围绕能力组织，而非假设每届都按完全相同的模型清单开展。

## 实验 / 项目

课程强调把已有模型放到新的测试环境中，观察领域偏移（Domain Shift）。报告不能停在“下载代码并跑通”：需要说明数据从哪里来、如何预处理、指标如何计算、哪些情况失败，以及可能原因是否得到实验支持。

建议采用四步证据链：

1. **建立基线**：固定源码版本、权重、依赖、数据与评价设置。
2. **迁移测试**：区分预训练模型直接推理、重新训练和微调，不能混称“复现”。
3. **分析误差**：检查图像分辨率、光照、坐标系、尺度、标注协议等可验证因素。
4. **开展对照**：一次只改变明确因素，同时记录质量、速度、显存等指标的适用条件。

自定义项目可涉及三维重建与新视角合成、生成模型，或已有任务的延伸。优先选能在期限内完成可靠评估的题目，而非只按模型规模决定难度。网页 Demo 展示可用性，但不替代定量结果，也不要公开含私人信息的采集数据。

## 往届经验与建议

**2026 秋版本。** 初始大纲笔记为互动与进度 10%、三个实验各 20%、自定义项目 30%；但后续 Project 2 通知笔记记为 30%，与初始表不一致。**不能将两个版本直接拼接成总评表**，本页也不替课程解决这一冲突。已知特点是项目、实验报告与展示占主要位置，而非以笔试为中心。

- **难点**：环境依赖与显存需求、数据协议、相机和坐标约定，以及把结果变化归因到具体因素。
- **准备**：先熟悉 PyTorch 数据管线、模型加载、训练 / 推理模式、随机种子和基本日志。不要等到报告前才检查是否存下了评估结果。
- **工具链**：隔离环境、固定依赖和权重来源；保留完整命令及配置。下载成功或保存了一张图片，不等于完成了方法复现。
- **项目组织**：分工时明确数据、实现、评估与报告接口；对照必须使用同一口径。未知项和失败结果如实保留。
- **报告**：区分观察、解释与尚待验证的假设；不把一组成功截图写成普遍性能结论。
