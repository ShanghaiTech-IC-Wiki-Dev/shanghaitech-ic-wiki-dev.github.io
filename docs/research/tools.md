# 科研工具与工作习惯

工具的价值是减少重复劳动、保留证据、让合作者能够接手，不是把所有软件装一遍。建议从“文献库 + Git 仓库 + 实验日志 + 自动绘图”起步，遇到真实需求再扩展。

## 文献：Zotero

[Zotero](https://www.zotero.org/)适合收集论文元数据、管理 PDF、加标签并导出引用。按研究问题建立集合，比只按会议年份分类更容易形成知识结构。

导入后检查标题、作者、年份、DOI 和会议 / 期刊；网页抓取可能把预印本、正式版和补充材料混在一起。对同一工作的不同版本保留说明，笔记注明实际阅读版本。同步前确认网盘、存储服务与合作协议允许上传的范围；能下载不等于能公开再分发。

## 写作：LaTeX 与 Overleaf

[LaTeX](https://www.latex-project.org/)适合公式、交叉引用与论文排版；[Overleaf](https://www.overleaf.com/)便于多人协作，但云端项目不能默认承载保密材料。使用会议或期刊官方模板，不靠缩小字号、压缩行距规避页数限制。

从开始就用引用键、图表标签和参考文献数据库，不手写“见图 3”。本地保存源文件、图、参考文献和编译说明；合作前约定主分支与合并方式，避免多人同时覆盖同一个文件。上传前清除注释中的私人信息、审稿身份线索与内部链接。

## 代码与实验：Git

[Git](https://git-scm.com/)记录源代码、配置和分析脚本的演变，不能代替数据备份。一次提交聚焦一个变化，说明为什么改；重要结果绑定提交版本、命令、依赖与输入。

- 将许可证文件、密钥、账号配置、工艺设计套件（Process Design Kit，PDK）、大体积结果与私有数据排除在公开仓库外。
- 不对共享仓库随意强制推送，不覆盖他人的未提交修改。
- 敏感文件一旦进入历史，删除工作区文件并不能消除泄露；应立即通知资源管理员并按要求撤销凭据。
- 实验产物另做有版本的备份，保存清楚的源代码与数据对应关系。

## 绘图：Python + Matplotlib

[Matplotlib](https://matplotlib.org/)适合从原始数据生成可重复的图。将数据处理与作图写成脚本，保留单位、筛选规则和统计口径，避免只保存最后一张图片。

线图要说明横纵轴和误差来源；柱状图不能通过任意截断纵轴夸大差异；多次实验报告重复次数与波动。优先输出 PDF 或 SVG 等矢量格式，在最终论文尺寸下检查文字是否可读。原始数据、清洗后数据和展示数据分层保存，不能为了好看删掉不利样本。

## 框图：draw.io 与 Inkscape

[draw.io / diagrams.net](https://www.diagrams.net/)适合流程图、系统框图；[Inkscape](https://inkscape.org/)适合矢量图编辑。保存可编辑源文件，统一字体、线宽、箭头和颜色语义。用形状或线型辅助区分，避免只依赖红绿色。

重绘论文框图应注明“改绘自”及出处；说明性插图不能被当成测量结果。不要截屏一张低清图片，再靠放大补救。

## Linux 服务器：先问规则，再跑任务

远程计算前确认账号权限、存储配额、调度系统、CPU / GPU / 内存预算和许可证限制。长任务使用管理员推荐的作业方式；交互会话、日志和检查点应能支持故障恢复。

先在小输入上验证流程，记录启动命令、环境、作业 ID、输出路径和停止方式。不要抢占他人的 GPU、终止不属于自己的进程、在登录节点跑重计算，或将共享目录当成永久备份。学习环境准备可继续看[EDA 环境](/tools/development/)；校内资源入口见[平台资源](/shanghaitech/research-groups/)。

## AI 辅助：可加速，不能代替责任

合适的用途包括解释公开概念、生成检索关键词、润色自己写的英文、协助发现代码问题和检查图表表述。使用后仍需回到教材、论文、工具手册和实际运行结果核验。

::: warning 不可越过的红线
不要向未经批准的外部服务上传 NDA 材料、PDK、商业 EDA 日志中的敏感内容、未公开网表、学生个人信息或未发表合作成果。不得伪造引用、实验数据、审稿意见和贡献；不得把生成代码直接当作已验证实现。课程与投稿中的 AI 使用还须遵守相应政策，必要时披露。
:::

一个可靠习惯是把“AI 建议”“自己采纳的改动”“实际验证的结果”分开记录。模型说“应该能运行”，不是测试通过；润色后的专业句子更流畅，也不意味着事实更准确。
