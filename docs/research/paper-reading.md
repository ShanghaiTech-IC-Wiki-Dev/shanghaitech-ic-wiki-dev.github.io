# 论文阅读与讨论组

读论文的目标不是逐句翻译，而是理解“作者为什么这样做、证据支持到哪里、我能如何验证”。先明确阅读目的：了解领域、寻找基线、复现方法，还是为某个设计决策找依据。不同目的需要不同深度，不必每篇都精读。

## 三遍读法

### 第一遍：建立地图

用约 10–20 分钟看标题、摘要、引言、主要图表和结论，暂时跳过推导。回答七个问题：解决什么问题、为什么难、现有方法哪里不够、关键观察是什么、核心机制是什么、哪个结果最有说服力、有哪些前提与局限。最后写一句自己的总结，再决定是否继续。

标题中的“高效”“可扩展”不是结论。必须追问：相对哪个基线，在什么设置下，用什么指标？看不懂的术语先记入清单，不要被一个生词拖住全部阅读。

### 第二遍：追踪机制与证据

按数据流阅读方法，把总体框架拆成“输入 → 操作 → 输出 → 有效原因 → 代价”。定义公式中的符号、单位、假设与边界条件。逐张检查关键图表，区分论文原文事实、帮助理解的解释、自己的推断。

IC 论文尤其需要记录技术节点、供电电压、频率、面积、功耗、存储容量、位宽、工作负载和测试条件。区分实测、后仿真、综合估计与理论分析；峰值吞吐不能直接当端到端速度，跨工艺归一化也不能自动证明公平。

### 第三遍：尝试重建

合上论文，画出框图、解释关键推导，或实现最小模型。复现前固定论文版本、代码提交、依赖与配置，先运行作者基线，再改一个变量。若结果不符，记录差异和排查过程，不通过换口径把数字“对齐”。

第三遍不一定意味着完整流片。重算一个关键表格、复现一段算法、构造反例，都是检验理解的方法。明确哪些内容已经验证，哪些只是相信作者的报告。

## 可复制的阅读模板

```text
论文：标题、作者、年份、会议/期刊、版本、DOI 或原文链接
阅读目的：这篇论文要帮我回答什么？
一句话：在什么条件下，用什么机制解决什么问题？
背景与缺口：已有方法的能力和具体瓶颈
方法：输入 → 操作 → 输出 → 为什么有效 → 代价
关键证据：Figure / Table / Section 与对应结论
实验条件：工艺/平台、频率、精度、工作负载、基线、测量范围
局限：原文承认的问题 / 自己尚未验证的判断
复现记录：版本、配置、命令、日志位置、结果与偏差
横向比较：与已读工作的共同假设和关键差别
待解问题：哪些结论仍缺证据？
下一次第一步：一个能立即开始的小任务
```

笔记不必复制论文目录。重要的是让未来的自己能找到原始依据。数字要回原表核查；预印本与正式版可能不同，不能混用两个版本的结果。引用原图时标明出处，自己重画的解释图不能冒充作者实验。

## 如何组织 reading group / journal club

读书组（Reading Group）适合围绕连续主题逐步补齐知识；期刊俱乐部（Journal Club）可围绕单篇新工作讨论。不论名称，都应先选一个问题，而不是只追逐最新论文。

- **会前**：明确主讲、主持和记录角色，提前分享原文版本、必读图表与两三个问题。主讲者准备背景，参与者至少完成第一遍阅读。
- **会中**：可按 45–60 分钟组织：30 秒结论、问题与背景、核心方法、实验与公平性、开放讨论。时间仅是组织建议，不是固定制度。遇到推导分歧，先回到符号和假设，不用“作者肯定是对的”结束讨论。
- **会后**：纪要按“结论 → 讲懂的机制 → 未解问题 → 行动项”整理。为行动项写明负责人、产物与约定时间，但公开版应移除个人与内部项目细节。

主题主页可维护一张精读表，字段为论文、问题、机制、证据、局限和复现入口；另设跨论文连接与下一次第一步。不要把聊天流水账当研究积累，也不要未经同意录音或公开组会材料。
