# 学术写作与汇报

好的科研表达不是把工作包装得更大，而是让读者迅速明白：问题是什么、已有方法为什么不够、你的方法如何工作、证据能支持多强的结论。动笔前先写一句主张，再列出支持它所需的图表和实验，往往比先写长篇背景更有效。

## 论文的基本结构

| 部分 | 需要回答的问题 | 常见误区 |
| --- | --- | --- |
| 标题与摘要 | 做了什么，为什么重要，主要证据是什么？ | 只写形容词，不给条件和结果 |
| 引言 | 具体缺口是什么，为什么值得解决？ | 泛谈产业背景，找不到研究问题 |
| 背景与相关工作 | 与最接近工作有何共同假设和不同？ | 堆引用，或把比较对象故意写弱 |
| 方法 / 电路 / 架构 | 机制如何产生收益，付出了什么代价？ | 只贴框图，不解释数据流和设计理由 |
| 实验 / 测量 | 证据是否公平、可复现且足够？ | 换平台、换精度后直接比数字 |
| 讨论与局限 | 哪些条件下不成立，还有哪些风险？ | 把推测写成已验证事实 |
| 结论 | 最重要的发现及其边界是什么？ | 新增正文未论证的宏大结论 |

电路论文常需要测试芯片与测量结果；架构论文需要工作负载和模拟方法；EDA 论文需要约束、基准与运行时间。先看目标 venue 的近年文章与官方模板，不照搬另一个领域的结构。

## 先做图表，再组织叙事

一张图只承担一个主要信息。框图交代输入、输出、时钟域、存储和接口；性能图说明基线、单位、工作负载与测量范围；芯片显微照片和版图不要混称。表格对齐精度、工艺、频率和面积口径，标明实测、仿真或估算。

图表规范包括：

- 图注可独立理解，缩写首次定义；坐标轴写变量与单位。
- 统一有效数字和小数位，不用无意义的精度制造可信感。
- 统计图说明重复次数、误差条与聚合方式；不能只挑最佳结果。
- 消融实验一次隔离一个机制，说明性能收益伴随的面积、能耗或复杂度代价。
- 使用矢量图，检查打印和灰度效果，在论文实际尺寸下审阅文字。
- 引用、改绘或使用第三方图片时标明来源，必要时取得许可。

跨节点归一化、峰值能效与端到端性能等存在假设，必须明确计算方式。不要把估算与实测放在同一列却不标识。

## 英文写作

先用清楚的短句写准确，再追求简练。每段围绕一个中心，段首给主题句，后文提供证据或解释。让主语明确承担动作，避免连续使用模糊的 “it” 或 “this”。“significant” 若无统计意义应谨慎使用；“first” 和 “state-of-the-art” 需要明确检索与比较边界。

术语、时态、符号和缩写保持一致。润色工具只能帮助表达，不能决定技术含义；改写后重新核对否定、因果、比较对象和数字。参考文献由原文或可靠数据库导出，不采信生成式工具编出的条目。

## 投稿与 rebuttal

投稿前核对篇幅、双盲、作者列表、利益冲突、伦理、数据代码和 AI 使用规则。作者顺序与贡献应及早讨论；未获所有作者认可，不擅自提交。不能一稿多投，也不能把已发表结果换个标题重复投稿。

审稿回复（Rebuttal）先按重要性整理问题，再逐条回应：“审稿人关切 → 直接回答 → 证据位置 → 拟修改内容”。承认真实缺陷，不攻击审稿人；不同意时用证据说明假设和口径。补充实验必须真实可追溯，并遵守回复阶段的材料限制。拒稿后先修正实质问题，不只换模板。

## 组会与答辩 slide 怎么组织

以一个 10–15 分钟汇报为例，可用以下顺序，按场合调整页数：

1. 问题与一句话结论：让听众知道为什么听。
2. 背景和最接近基线：只介绍理解后文所需内容。
3. 关键观察：说明设计选择的来源。
4. 总体方案：用一张图建立地图，再解释关键模块。
5. 最有说服力的结果：每页一个结论，图表旁直接标明比较条件。
6. 失败、局限与下一步：组会可以集中讨论尚未解决的问题。
7. 总结与备份页：把推导、完整表格和配置细节放在备份页供问答。

答辩要明确个人贡献与合作边界；组会不要把遇到的问题藏到最后一分钟。提前计时演练，用投影距离检查字号，避免整页论文截图。遇到不会的问题，说明当前已知、未知和核验办法，比临时编造更专业。
